`asyncio` lets Python handle many waiting operations concurrently, especially network calls, APIs, database queries, sockets, and timers. The core concepts are **coroutines**, the **event loop**, `async`/`await`, tasks, `gather()`, timeouts, and cancellation. `asyncio` is mainly for I/O-bound concurrency—not for making CPU-heavy Python code execute in parallel.[[docs.python](https://docs.python.org/3/library/asyncio.html)]

# 1. Why asynchronous programming?

Suppose you call three APIs sequentially:

```
result_a = call_api_a()
result_b = call_api_b()
result_c = call_api_c()
```

If each takes two seconds, the total may be about:

```
2 + 2 + 2 = 6 seconds
```

While waiting for API A, your program is doing nothing.

Asynchronous code can start all three operations and use the waiting time efficiently:

```
result_a, result_b, result_c = await asyncio.gather(
    call_api_a(),
    call_api_b(),
    call_api_c(),
)
```

The total may be close to:

```
2 seconds
```

assuming the operations wait concurrently.

This is useful for:

- Calling several AI APIs.
- Querying multiple data sources.
- Running parallel retrieval operations.
- Handling many HTTP requests.
- Reading from sockets.
- Managing WebSocket connections.
- Waiting for database responses.
- Building asynchronous agent tools.

`asyncio` is designed for concurrent code using `async`/`await` and provides high-level APIs for running coroutines, networking, synchronization, subprocesses, and queues.[[docs.python](https://docs.python.org/3/library/asyncio.html)]

# 2. Synchronous versus asynchronous

## Synchronous code

```
import time


def task(name, seconds):
    print(f"{name} started.")
    time.sleep(seconds)
    print(f"{name} finished.")
```

```
task("A", 2)
task("B", 2)
```

Output:

```
A started.
A finished.
B started.
B finished.
```

Approximate duration:

```
4 seconds
```

`time.sleep()` blocks the entire thread.

## Asynchronous code

```
import asyncio


async def task(name, seconds):
    print(f"{name} started.")

    await asyncio.sleep(seconds)

    print(f"{name} finished.")
```

```
async def main():
    await asyncio.gather(
        task("A", 2),
        task("B", 2),
    )
```

Run it:

```
asyncio.run(main())
```

Output:

```
A started.
B started.
A finished.
B finished.
```

Approximate duration:

```
2 seconds
```

The key difference is:

```
time.sleep(2)       # Blocks the thread
await asyncio.sleep(2)  # Suspends this coroutine
```

# 3. `async def`: defining a coroutine

A function defined with:

```
async def
```

is an asynchronous function.

```
async def greet():
    return "Hello, Toussaint!"
```

Calling it does not immediately return the string:

```
result = greet()

print(result)
```

You get a coroutine object similar to:

```
<coroutine object greet at 0x...>
```

To receive the result, use:

```
await
```

inside another asynchronous function:

```
async def main():
    message = await greet()
    print(message)
```

Then start the top-level coroutine:

```
import asyncio

asyncio.run(main())
```

Output:

```
Hello, Toussaint!
```

## Important rule

You can use:

```
await
```

only inside an:

```
async def
```

function, except in environments such as the interactive asyncio REPL or some notebooks that support top-level `await`.

# 4. What does `await` mean?

`await` means:

> Pause this coroutine until the awaitable operation finishes, while allowing the event loop to run other work.

```
async def fetch_data():
    print("Starting request.")

    await asyncio.sleep(2)

    print("Request complete.")

    return {"status": "ok"}
```

When this line executes:

```
await asyncio.sleep(2)
```

the coroutine pauses. The event loop can run another coroutine during those two seconds.

`await` can be used with:

- Coroutines
- Tasks
- Futures
- Other awaitable objects

It cannot be used with an ordinary synchronous function:

```
def normal_function():
    return "Done"
```

This is wrong:

```
result = await normal_function()
```

because a normal string is not awaitable.

Correct:

```
result = normal_function()
```

# 5. The event loop

The **event loop** is the engine that schedules and resumes asynchronous work.

Conceptually:

```
Coroutine A starts
        ↓
Coroutine A waits for network response
        ↓
Event loop pauses A
        ↓
Coroutine B runs
        ↓
Coroutine B waits
        ↓
Coroutine A's response arrives
        ↓
Event loop resumes A
```

The event loop does not make blocking code magically asynchronous.

This blocks the event loop:

```
import time


async def bad_task():
    time.sleep(5)
```

While `time.sleep(5)` runs, other async tasks cannot make progress in that event loop thread.

Use:

```
await asyncio.sleep(5)
```

for an asynchronous delay.

The high-level recommended entry point is:

```
asyncio.run(main())
```

It creates and manages an event loop, runs the awaitable, finalizes asynchronous generators, shuts down the executor, and closes the loop. It should generally be used once as the main entry point.[[docs.python](https://docs.python.org/3/library/asyncio-runner.html)]

# 6. `asyncio.run()`

Complete program:

```
import asyncio


async def main():
    print("Async program started.")
    await asyncio.sleep(1)
    print("Async program finished.")


if __name__ == "__main__":
    asyncio.run(main())
```

Run:

```
python app.py
```

Output:

```
Async program started.
Async program finished.
```

## Do not call it inside a running event loop

This is usually wrong inside an asynchronous function:

```
async def main():
    asyncio.run(other_task())
```

You may get:

```
RuntimeError: asyncio.run() cannot be called from a running event loop
```

Use:

```
async def main():
    await other_task()
```

In Jupyter notebooks or environments that already run an event loop, use:

```
await main()
```

instead of:

```
asyncio.run(main())
```

# 7. Sequential `await`

This code is asynchronous but sequential:

```
import asyncio


async def fetch(name, delay):
    print(f"{name} started.")
    await asyncio.sleep(delay)
    print(f"{name} finished.")
    return name


async def main():
    first = await fetch("First", 2)
    second = await fetch("Second", 2)

    print(first, second)


asyncio.run(main())
```

Execution:

```
First started.
First finished.
Second started.
Second finished.
```

Approximate duration:

```
4 seconds
```

`async` does not automatically mean concurrent.

This:

```
await first_operation()
await second_operation()
```

waits for the first before starting the second.

To run them concurrently, use tasks or `gather()`.

# 8. `asyncio.create_task()`

`create_task()` schedules a coroutine to run concurrently and returns a `Task`.

```
import asyncio


async def fetch(name, delay):
    print(f"{name} started.")
    await asyncio.sleep(delay)
    print(f"{name} finished.")
    return name


async def main():
    task_a = asyncio.create_task(
        fetch("A", 2)
    )

    task_b = asyncio.create_task(
        fetch("B", 2)
    )

    result_a = await task_a
    result_b = await task_b

    print(result_a, result_b)


asyncio.run(main())
```

Output:

```
A started.
B started.
A finished.
B finished.
A B
```

The tasks begin once control returns to the event loop.

`asyncio.create_task()` wraps a coroutine in a task and schedules it to run soon.[[docs.python](https://docs.python.org/3/library/asyncio-task.html)]

## Naming tasks

```
task = asyncio.create_task(
    fetch("A", 2),
    name="fetch-provider-a",
)
```

Inspect the name:

```
print(task.get_name())
```

Task names are useful for debugging and observability.

# 9. `asyncio.gather()`

`gather()` runs multiple awaitables concurrently and returns their results in the same order as the supplied awaitables.[[docs.python](https://docs.python.org/3/library/asyncio-task.html)]

```
import asyncio


async def fetch(name, delay):
    await asyncio.sleep(delay)
    return f"Result from {name}"


async def main():
    results = await asyncio.gather(
        fetch("A", 2),
        fetch("B", 1),
        fetch("C", 3),
    )

    print(results)


asyncio.run(main())
```

Output:

```
[
    "Result from A",
    "Result from B",
    "Result from C",
]
```

Although C finishes last, the result order remains:

```
A, B, C
```

because that is the input order.

Approximate duration:

```
3 seconds
```

not:

```
2 + 1 + 3 = 6 seconds
```

# 10. `gather()` and exceptions

By default:

```
return_exceptions=False
```

If one awaitable raises an exception, `gather()` propagates the first exception to the caller.

```
import asyncio


async def successful_task():
    await asyncio.sleep(1)
    return "Success"


async def failing_task():
    await asyncio.sleep(0.5)
    raise ValueError("Task failed.")


async def main():
    results = await asyncio.gather(
        successful_task(),
        failing_task(),
    )

    print(results)
```

The `ValueError` is raised from `gather()`.

Important: with the default behavior, other awaitables are not automatically cancelled merely because one raises; they may continue running.[[docs.python](https://docs.python.org/3/library/asyncio-task.html)]

## Collect exceptions as results

```
async def main():
    results = await asyncio.gather(
        successful_task(),
        failing_task(),
        return_exceptions=True,
    )

    for result in results:
        if isinstance(result, Exception):
            print(f"Failed: {result}")
        else:
            print(f"Success: {result}")
```

Possible output:

```
Success: Success
Failed: Task failed.
```

Use `return_exceptions=True` when you want to process every result independently.

For example, querying several model providers:

```
responses = await asyncio.gather(
    ask_local_model(prompt),
    ask_cloud_model(prompt),
    ask_backup_model(prompt),
    return_exceptions=True,
)
```

Then choose successful responses while recording failures.

# 11. `gather()` versus `TaskGroup`

Modern Python also provides:

```
asyncio.TaskGroup
```

which offers structured concurrency. A task group waits for all tasks when its context exits and has stronger safety behavior around related task failures.[[docs.python](https://docs.python.org/3/library/asyncio-task.html)]

```
import asyncio


async def fetch(name, delay):
    await asyncio.sleep(delay)
    return f"Result from {name}"


async def main():
    async with asyncio.TaskGroup() as group:
        task_a = group.create_task(
            fetch("A", 2)
        )

        task_b = group.create_task(
            fetch("B", 1)
        )

    print(task_a.result())
    print(task_b.result())


asyncio.run(main())
```

## Which should you use?

Use `gather()` when:

```
You want a simple list of results.
```

Use `TaskGroup` when:

```
You are managing related tasks and want structured lifecycle and failure handling.
```

For new production code involving several related tasks, `TaskGroup` is often the safer design.

## Important behavior

With a `TaskGroup`, if one task fails:

- The other tasks in the group are generally cancelled.
- The group waits for cancellation to finish.
- Exceptions are propagated as an exception group.

This is often preferable when partial completion would be unsafe.

Example:

```
async def process_pipeline():
    async with asyncio.TaskGroup() as group:
        group.create_task(save_ticket())
        group.create_task(save_audit_record())
```

If saving the ticket fails, allowing the audit task to continue independently may be undesirable. A task group gives you a more structured failure boundary.

# 12. `asyncio.timeout()`

Use a timeout to prevent an async operation from waiting forever.

```
import asyncio


async def slow_operation():
    await asyncio.sleep(5)
    return "Finished"


async def main():
    try:
        async with asyncio.timeout(2):
            result = await slow_operation()
            print(result)

    except TimeoutError:
        print("Operation timed out.")


asyncio.run(main())
```

Output:

```
Operation timed out.
```

`asyncio.timeout()` is an asynchronous context manager. If the operation exceeds the deadline, it cancels the current task internally and converts the cancellation into a built-in `TimeoutError` that can be handled outside the context.[[docs.python](https://docs.python.org/3/library/asyncio-task.html)]

## Where to catch `TimeoutError`

Catch it outside:

```
try:
    async with asyncio.timeout(2):
        await operation()
except TimeoutError:
    ...
```

Not usually inside:

```
async with asyncio.timeout(2):
    try:
        await operation()
    except TimeoutError:
        ...
```

The timeout context manager transforms the internal cancellation when it exits, so catching outside is the correct pattern.

---

# 13. `asyncio.wait_for()`

Another timeout form is:

```
await asyncio.wait_for(
    operation(),
    timeout=2,
)
```

Example:

```
async def main():
    try:
        result = await asyncio.wait_for(
            slow_operation(),
            timeout=2,
        )

        print(result)

    except TimeoutError:
        print("Timed out.")
```

## `timeout()` versus `wait_for()`

|Feature|`asyncio.timeout()`|`asyncio.wait_for()`|
|---|---|---|
|Style|Context manager|Awaitable wrapper|
|Covers|A block containing multiple awaits|One awaitable|
|Can contain several operations|Yes|No|
|Can be rescheduled|Yes|No|
|Good for|Whole operation scope|Single coroutine timeout|

Use:

```
asyncio.wait_for(operation(), 5)
```

for one operation.

Use:

```
async with asyncio.timeout(5):
    ...
```

for a block containing multiple operations.

# 14. Nested and rescheduled timeouts

You can safely nest timeout contexts:

```
async def main():
    try:
        async with asyncio.timeout(10):
            async with asyncio.timeout(3):
                await operation()

    except TimeoutError:
        print("A timeout occurred.")
```

You can start without a deadline and set one later:

```
async def main():
    try:
        async with asyncio.timeout(None) as timeout:
            deadline = (
                asyncio.get_running_loop().time()
                + 5
            )

            timeout.reschedule(deadline)

            await slow_operation()

    except TimeoutError:
        print("Timed out.")
```

A timeout object can also tell you whether it expired:

```
async def main():
    async with asyncio.timeout(2) as timeout:
        try:
            await slow_operation()
        except TimeoutError:
            pass

    if timeout.expired():
        print("The deadline was exceeded.")
```

For normal use, the simple form is enough:

```
try:
    async with asyncio.timeout(5):
        await operation()
except TimeoutError:
    ...
```

# 15. Cancellation

Cancellation means asking an async task to stop.

```
import asyncio


async def worker():
    try:
        while True:
            print("Working...")
            await asyncio.sleep(1)

    except asyncio.CancelledError:
        print("Worker cleanup.")
        raise
```

```
async def main():
    task = asyncio.create_task(worker())

    await asyncio.sleep(2)

    task.cancel()

    try:
        await task
    except asyncio.CancelledError:
        print("Task cancelled.")


asyncio.run(main())
```

Possible output:

```
Working...
Working...
Worker cleanup.
Task cancelled.
```

## Always clean up cancellation

Use:

```
try:
    ...
finally:
    cleanup()
```

or:

```
except asyncio.CancelledError:
    cleanup()
    raise
```

Do not silently swallow cancellation:

```
except asyncio.CancelledError:
    return
```

Cancellation is how timeouts, task groups, shutdown signals, and application supervisors stop work.

# 16. Cancellation and `finally`

```
async def worker():
    resource = await acquire_resource()

    try:
        await do_work(resource)

    finally:
        await release_resource(resource)
```

If the task is cancelled while `do_work()` is running, the `finally` block still executes, allowing cleanup.

This is critical for:

- Database connections
- Locks
- Temporary files
- HTTP sessions
- Model resources
- Streaming responses
- Agent tool sessions

# 17. Blocking code inside async functions

This is one of the most important practical problems.

Bad:

```
import time


async def bad():
    time.sleep(5)
```

This blocks the event loop for five seconds.

Other async operations cannot run during that time.

## Use an async library

Instead of synchronous HTTP:

```
requests.get(url)
```

use an async HTTP client such as `aiohttp` or `httpx.AsyncClient`.

Instead of synchronous database drivers, use an async-compatible database library where appropriate.

## Move blocking work to a thread

```
import asyncio


def blocking_function():
    return expensive_or_blocking_work()
```

```
async def main():
    result = await asyncio.to_thread(
        blocking_function
    )

    print(result)
```

`asyncio.to_thread()` runs a blocking function in a separate thread so it does not block the event loop.

Use this for:

- Blocking file operations
- Legacy synchronous SDKs
- CPU-light but blocking functions
- Synchronous database clients
- Synchronous APIs that cannot be replaced immediately

## CPU-heavy work

Threads may not provide ideal speedups for CPU-heavy pure Python code because of the GIL.

For heavy CPU work, consider:

- `ProcessPoolExecutor`
- Multiprocessing
- NumPy/vectorized operations
- Native libraries
- Separate worker services
- Distributed task queues

The basic rule:

```
I/O-bound waiting → asyncio
CPU-bound computation → processes or specialized compute
```

# 18. Async context managers

As you learned with normal context managers:

```
with resource:
    ...
```

Asynchronous resources use:

```
async with resource:
    ...
```

They implement:

```
__aenter__
__aexit__
```

Example:

```
class AsyncSession:
    async def __aenter__(self):
        print("Opening session.")
        return self

    async def fetch(self, url):
        await asyncio.sleep(1)
        return f"Fetched {url}"

    async def __aexit__(
        self,
        exc_type,
        exc_value,
        traceback,
    ):
        print("Closing session.")
```

Use it:

```
async def main():
    async with AsyncSession() as session:
        result = await session.fetch(
            "https://example.com"
        )

        print(result)
```

This is useful for:

- Async HTTP clients
- Async database sessions
- WebSockets
- Async locks
- Async file libraries
- Message consumers

# 19. Async iterators

An async iterator supports:

```
async for
```

through:

```
__aiter__
__anext__
```

Example:

```
class EventStream:
    def __init__(self, events):
        self.events = events
        self.index = 0

    def __aiter__(self):
        return self

    async def __anext__(self):
        if self.index >= len(self.events):
            raise StopAsyncIteration

        await asyncio.sleep(0.5)

        event = self.events[self.index]
        self.index += 1

        return event
```

Use it:

```
async def main():
    stream = EventStream([
        "ticket.created",
        "ticket.classified",
        "ticket.closed",
    ])

    async for event in stream:
        print(event)
```

Output:

```
ticket.created
ticket.classified
ticket.closed
```

This is useful for:

- Streaming model tokens
- Event streams
- WebSocket messages
- Async database cursors
- Message queues
- Real-time agent events

# 20. Async generators

Often an async generator is simpler:

```
async def event_stream():
    events = [
        "ticket.created",
        "ticket.classified",
        "ticket.closed",
    ]

    for event in events:
        await asyncio.sleep(0.5)
        yield event
```

Use it:

```
async def main():
    async for event in event_stream():
        print(event)
```

Async generators combine:

```
async
yield
```

They are natural for streaming data.

# 21. Async locks

Async tasks can interfere with shared state.

Use:

```
asyncio.Lock()
```

```
class AsyncCounter:
    def __init__(self):
        self.value = 0
        self.lock = asyncio.Lock()

    async def increment(self):
        async with self.lock:
            current = self.value

            await asyncio.sleep(0)

            self.value = current + 1
```

The lock ensures only one task modifies the critical section at a time.

Use:

```
async with self.lock:
    ...
```

not:

```
with self.lock:
    ...
```

because this is an asynchronous lock.

Other synchronization tools include:

```
asyncio.Event
asyncio.Condition
asyncio.Semaphore
asyncio.BoundedSemaphore
asyncio.Queue
```

# 22. Async semaphores and concurrency limits

Launching thousands of API requests at once can overwhelm:

- Your machine
- The provider
- Network connections
- Rate limits
- Memory
- Database capacity

Use a semaphore to limit concurrency.

```
import asyncio


semaphore = asyncio.Semaphore(3)
```

```
async def limited_request(name):
    async with semaphore:
        print(f"{name} started.")
        await asyncio.sleep(1)
        print(f"{name} finished.")

        return name
```

```
async def main():
    results = await asyncio.gather(
        *[
            limited_request(f"Request {index}")
            for index in range(10)
        ]
    )

    print(results)
```

At most three requests are inside the semaphore-protected block at once.

This is very important for:

- LLM API calls
- Web scraping
- Batch embeddings
- Customer notifications
- Database queries
- Tool execution
- Concurrent file processing

# 23. Async queues

An `asyncio.Queue` allows producers and consumers to coordinate.

```
import asyncio


async def producer(queue):
    for item in range(5):
        await queue.put(item)
        print(f"Produced {item}")

    await queue.put(None)
```

```
async def consumer(queue):
    while True:
        item = await queue.get()

        if item is None:
            queue.task_done()
            break

        print(f"Consumed {item}")
        queue.task_done()
```

```
async def main():
    queue = asyncio.Queue()

    await asyncio.gather(
        producer(queue),
        consumer(queue),
    )
```

For multiple consumers or more complex pipelines, use sentinel values carefully or track worker completion separately.

Queues are useful for:

```
producer → preprocessing → classifier → storage
```

or:

```
incoming tickets → workers → model provider → results
```

# 24. Realistic AI-provider example

```
import asyncio


async def ask_provider(
    provider_name: str,
    prompt: str,
    delay: float,
) -> str:
    print(f"Calling {provider_name}.")

    await asyncio.sleep(delay)

    return (
        f"{provider_name} response "
        f"for: {prompt}"
    )
```

Query multiple providers:

```
async def compare_providers(prompt: str):
    responses = await asyncio.gather(
        ask_provider(
            "local-model",
            prompt,
            1.5,
        ),
        ask_provider(
            "cloud-model",
            prompt,
            2.0,
        ),
        ask_provider(
            "backup-model",
            prompt,
            1.0,
        ),
        return_exceptions=True,
    )

    return responses
```

Add a timeout:

```
async def safe_compare(prompt: str):
    try:
        async with asyncio.timeout(5):
            return await compare_providers(prompt)

    except TimeoutError:
        return ["Provider comparison timed out."]
```

Run:

```
async def main():
    results = await safe_compare(
        "Classify this support request."
    )

    for result in results:
        print(result)


asyncio.run(main())
```

This pattern can be extended with:

- Provider-specific timeouts.
- Retries.
- Semaphores.
- Circuit breakers.
- Cancellation.
- Structured logging.
- Response validation.
- Fallback selection.
- Cost tracking.

# 25. Per-operation timeout

A single overall timeout may not be enough.

```
async def ask_with_timeout(
    provider_name: str,
    prompt: str,
    timeout_seconds: float,
):
    try:
        async with asyncio.timeout(
            timeout_seconds
        ):
            return await ask_provider(
                provider_name,
                prompt,
                2.0,
            )

    except TimeoutError:
        return (
            f"{provider_name} timed out."
        )
```

Then:

```
async def main():
    results = await asyncio.gather(
        ask_with_timeout(
            "local",
            "Classify ticket.",
            1.0,
        ),
        ask_with_timeout(
            "cloud",
            "Classify ticket.",
            3.0,
        ),
    )

    print(results)
```

Each provider receives its own deadline.

# 26. Event loop access

Usually, do not manually manage the event loop.

Prefer:

```
asyncio.run(main())
```

Inside an async function, use:

```
loop = asyncio.get_running_loop()
```

Example:

```
async def main():
    loop = asyncio.get_running_loop()

    current_time = loop.time()

    print(current_time)
```

Use the loop’s monotonic clock for deadlines:

```
deadline = (
    asyncio.get_running_loop().time()
    + 10
)
```

Do not use wall-clock time for duration deadlines if clock adjustments could matter.

## Low-level loop functions

You may see:

```
loop = asyncio.new_event_loop()
asyncio.set_event_loop(loop)
loop.run_until_complete(main())
loop.close()
```

This is low-level code and rarely necessary for application code.

Use it when:

- Writing frameworks.
- Embedding asyncio.
- Integrating custom event loops.
- Controlling loop lifecycle manually.
- Building advanced test infrastructure.

The high-level runner is the normal entry point.[[docs.python](https://docs.python.org/3/library/asyncio-runner.html)]

# 27. Debug mode

You can enable asyncio debug mode:

```
asyncio.run(main(), debug=True)
```

Or:

```
PYTHONASYNCIODEBUG=1 python app.py
```

Debug mode can help identify:

- Slow callbacks.
- Coroutines that were never awaited.
- Resource warnings.
- Incorrect event-loop usage.
- Some blocking operations.

Example warning source:

```
async def main():
    task = async_operation()
    # Forgot: await task
```

The coroutine may generate a warning because it was created but never awaited.

Correct:

```
await async_operation()
```

or:

```
asyncio.create_task(async_operation())
```

when you intentionally schedule it.

# 28. Common mistakes

## Calling an async function without awaiting

Incorrect:

```
result = fetch_data()
print(result)
```

Correct:

```
result = await fetch_data()
```

inside `async def`.

---

## Using `asyncio.run()` repeatedly

Avoid:

```
for item in items:
    asyncio.run(process(item))
```

This creates and closes an event loop for every item.

Better:

```
async def main():
    await asyncio.gather(
        *(process(item) for item in items)
    )


asyncio.run(main())
```

---

## Blocking the event loop

Avoid:

```
time.sleep(5)
requests.get(url)
```

inside async code.

Use async-compatible operations or:

```
await asyncio.to_thread(
    blocking_function
)
```

---

## Creating tasks and losing references

Avoid:

```
asyncio.create_task(background_work())
```

without deciding how task lifetime and errors will be handled.

Better:

```
task = asyncio.create_task(background_work())

try:
    await task
except Exception:
    ...
```

Or use:

```
async with asyncio.TaskGroup() as group:
    group.create_task(background_work())
```

---

## Launching unlimited requests

Avoid:

```
await asyncio.gather(
    *[
        call_api(item)
        for item in thousands_of_items
    ]
)
```

Use a semaphore, queue, batching, or a worker pool.

---

## Swallowing cancellation

Avoid:

```
except asyncio.CancelledError:
    pass
```

Usually clean up and re-raise:

```
except asyncio.CancelledError:
    await cleanup()
    raise
```

---

## Assuming async means parallel CPU execution

This does not make heavy computation parallel:

```
async def calculate():
    for _ in range(10_000_000):
        ...
```

The event loop can only switch when the coroutine reaches an `await`.

Use processes or specialized libraries for CPU-heavy work.

async def sequential():
    start = perf_counter()

    first = await task("A", 2)
    second = await task("B", 1)
    third = await task("C", 3)

    elapsed = perf_counter() - start

    return [first, second, third], elapsed

```
async def concurrent():
    start = perf_counter()

    results = await asyncio.gather(

        task("B", 1),

    elapsed = perf_counter() - start

    return results, elapsed
```

Run:

async def main():

        await sequential()

    concurrent_results, concurrent_time = (
        await concurrent()

    print(sequential_time)

    print(concurrent_results)
    print(concurrent_time)

## Exercise 5 answer

```
import asyncio


async def producer(
    queue: asyncio.Queue,
    tickets: list[str],
):
    for ticket in tickets:
        await queue.put(ticket)

    await queue.put(None)
```

```
async def classify(ticket: str) -> str:
    await asyncio.sleep(0.2)

    normalized = ticket.lower()

    if "payment" in normalized:
        return "billing"

    if "password" in normalized:
        return "account_access"

    return "general"
```

```
async def consumer(
    queue: asyncio.Queue,
):
    while True:
        ticket = await queue.get()

        try:
            if ticket is None:
                return

            category = await classify(ticket)

            print(
                f"{ticket} → {category}"
            )

        finally:
            queue.task_done()
```

```
async def main():
    queue = asyncio.Queue()

    tickets = [
        "I cannot reset my password",
        "My payment failed",
        "The page has an error",
    ]

    producer_task = asyncio.create_task(
        producer(queue, tickets)
    )

    consumer_task = asyncio.create_task(
        consumer(queue)
    )

    await producer_task
    await queue.join()
    await consumer_task


asyncio.run(main())
```

# 31. Final mental model

## Coroutine

Defined with:

```
async def
```

It describes asynchronous work.

```
async def fetch():
    ...
```

## `await`

Pauses the current coroutine while allowing other tasks to run:

```
result = await fetch()
```

## Event loop

Schedules and resumes async tasks:

```
task waits → event loop runs another task
```

## Task

A scheduled coroutine:

```
task = asyncio.create_task(coro())
```

## `gather()`

Runs multiple awaitables concurrently and returns results in input order:

```
results = await asyncio.gather(
    operation_a(),
    operation_b(),
)
```

## Timeout

Stops operations that exceed a deadline:

```
try:
    async with asyncio.timeout(5):
        await operation()
except TimeoutError:
    ...
```

## TaskGroup

Manages related tasks with structured concurrency:

```
async with asyncio.TaskGroup() as group:
    group.create_task(operation_a())
    group.create_task(operation_b())
```

## Blocking rule

```
Do not use blocking operations directly in async code.
```

Use:

```
await asyncio.sleep(...)
```

instead of:

```
time.sleep(...)
```

Use an async library or:

```
await asyncio.to_thread(blocking_function)
```

The essential pattern for an asynchronous Python program is:

```
import asyncio


async def main():
    results = await asyncio.gather(
        operation_a(),
        operation_b(),
    )

    return results


if __name__ == "__main__":
    results = asyncio.run(main())
```

For your AI-engineering projects, use `asyncio` for concurrent API calls, model-provider requests, retrieval, database I/O, agent tools, streaming responses, and event-driven pipelines. Use timeouts and concurrency limits by default when calling external services, and use `TaskGroup` when several related operations must be managed as one reliable unit.[[docs.python](https://docs.python.org/3/library/asyncio.html)][[docs.python](https://docs.python.org/3/library/asyncio-runner.html)][[docs.python](https://docs.python.org/3/library/asyncio-task.html)]
