`argparse` is Python’s standard-library tool for building command-line interfaces (CLIs). It lets users run your program with commands and options such as `--name`, `--verbose`, `--output`, and subcommands like `tickets list` or `tickets add`; it also generates help messages and validates invalid input automatically.[[docs.python](https://docs.python.org/3/howto/argparse.html)][[docs.python](https://docs.python.org/3/library/argparse.html)]

# 1. What is a CLI?

A CLI is a program controlled from a terminal.

For example:

```
python app.py
```

A more useful command:

```
python app.py --name Toussaint
```

Another example:

```
python tickets.py add --title "Cannot log in" --priority high
```

The text typed after the filename is available through:

```
sys.argv
```

Example:

```
import sys

print(sys.argv)
```

If you run:

```
python app.py hello 123
```

you may get:

```
["app.py", "hello", "123"]
```

You could manually inspect `sys.argv`, but that becomes difficult when your program needs:

- Required arguments
- Optional arguments
- Boolean flags
- Type conversion
- Default values
- Choices
- Help text
- Subcommands
- Validation
- Good error messages

`argparse` handles these tasks for you.

# 2. Your first `argparse` program

Create a file called:

```
greet.py
```

```
import argparse


parser = argparse.ArgumentParser(
    description="Greet a user."
)

parser.add_argument(
    "name",
    help="Name of the person to greet."
)

args = parser.parse_args()

print(f"Hello, {args.name}!")
```

Run it:

```
python greet.py Toussaint
```

Output:

```
Hello, Toussaint!
```

## What happened?

This line creates the parser:

```
parser = argparse.ArgumentParser(
    description="Greet a user."
)
```

This line declares a required positional argument:

```
parser.add_argument("name")
```

This line reads the command-line input:

```
args = parser.parse_args()
```

The result is a namespace object:

```
Namespace(name="Toussaint")
```

You access the value with:

```
args.name
```

```
python greet.py --help

```
usage: greet.py [-h] name

You can also write:

```
python greet.py -h

# 4. Positional arguments

A positional argument is identified by its position.

```
import argparse


parser = argparse.ArgumentParser(
    description="Add two numbers."
)

parser.add_argument("first")
parser.add_argument("second")

args = parser.parse_args()

print(args.first)
print(args.second)
```

Run:

```
python add.py 10 20
```

Output:

```
10
20
```

The first value goes into:

```
args.first
```

The second value goes into:

```
args.second
```

Positional arguments are usually required unless you configure them otherwise.

## Important limitation

By default, command-line values are strings.

```
parser.add_argument("first")
```

If you run:

```
python add.py 10 20
```

then:

```
args.first == "10"
args.second == "20"
```

This would concatenate strings:

```
print(args.first + args.second)
```

Output:

```
1020
```

To convert them to integers, use:

```
type=int
```

# 5. The `type` parameter

```
import argparse


parser = argparse.ArgumentParser(
    description="Add two integers."
)

parser.add_argument("first", type=int)
parser.add_argument("second", type=int)

args = parser.parse_args()

print(args.first + args.second)
```

Run:

```
python add.py 10 20
```

Output:

```
30
```

Now invalid input is handled automatically:

```
python add.py ten 20
```

Output will be similar to:

```
argument first: invalid int value: 'ten'
```

The parser converts the value by calling:

```
int("10")
```

You can use many conversion functions:

```
type=int
type=float
type=str
```

Example:

```
parser.add_argument("temperature", type=float)
```

You can also use your own conversion function.

# 6. Custom type functions

Suppose a username must be cleaned:

```
def username(value):
    value = value.strip().lower()

    if not value:
        raise argparse.ArgumentTypeError(
            "Username cannot be empty."
        )

    return value
```

Use it:

```
import argparse


def username(value):
    value = value.strip().lower()

    if not value:
        raise argparse.ArgumentTypeError(
            "Username cannot be empty."
        )

    return value


parser = argparse.ArgumentParser()

parser.add_argument(
    "username",
    type=username,
)

args = parser.parse_args()

print(f"Username: {args.username}")
```

Run:

```
python user.py "  TOUSSAINT  "
```

Output:

```
Username: toussaint
```

`argparse.ArgumentTypeError` creates a clear command-line validation error.

Another example:

```
def positive_integer(value):
    try:
        number = int(value)
    except ValueError as error:
        raise argparse.ArgumentTypeError(
            "Must be an integer."
        ) from error

    if number <= 0:
        raise argparse.ArgumentTypeError(
            "Must be greater than zero."
        )

    return number
```

```
parser.add_argument(
    "--workers",
    type=positive_integer,
    default=1,
)
```

# 7. Optional arguments

Optional arguments usually begin with:

```
-
```

or:

```
--
```

Example:

```
import argparse


parser = argparse.ArgumentParser(
    description="Greet a user."
)

parser.add_argument(
    "name",
    help="Name of the person to greet.",
)

parser.add_argument(
    "--title",
    help="Optional title.",
)

args = parser.parse_args()

if args.title:
    print(f"Hello, {args.title} {args.name}!")
else:
    print(f"Hello, {args.name}!")
```

Run:

```
python greet.py Toussaint --title Engineer
```

Output:

```
Hello, Engineer Toussaint!
```

Without `--title`:

```
python greet.py Toussaint
```

Output:

```
Hello, Toussaint!
```

Because `--title` is optional, its default value is:

```
None
```

# 8. Short and long options

You can provide both a short and long name:

```
parser.add_argument(
    "-n",
    "--name",
    help="Name of the user.",
)
```

Users can write either:

```
python app.py --name Toussaint
```

or:

```
python app.py -n Toussaint
```

Example:

```
import argparse


parser = argparse.ArgumentParser()

parser.add_argument(
    "-n",
    "--name",
    required=True,
)

args = parser.parse_args()

print(f"Hello, {args.name}!")
```

The destination attribute is automatically:

```
args.name
```

The long option normally determines the attribute name.

# 9. Required optional arguments

Although optional arguments are normally optional, you can make one required:

```
parser.add_argument(
    "--email",
    required=True,
)
```

Run without it:

```
python app.py
```

The parser reports that `--email` is required.

Use this only when the option truly must be supplied. A positional argument may be clearer if the value is always required:

```
python app.py user@example.com
```

instead of:

```
python app.py --email user@example.com
```

# 10. Default values

Use `default` to provide a fallback.

```
import argparse


parser = argparse.ArgumentParser()

parser.add_argument(
    "--host",
    default="127.0.0.1",
)

parser.add_argument(
    "--port",
    type=int,
    default=8000,
)

args = parser.parse_args()

print(args.host)
print(args.port)
```

Run:

```
python server.py
```

Output:

```
127.0.0.1
8000
```

Override the defaults:

```
python server.py --host 0.0.0.0 --port 9000
```

Output:

```
0.0.0.0
9000
```

Defaults make CLI tools easier to use because common behavior does not require long commands.

# 11. Boolean flags

A Boolean flag usually turns a feature on when present.

Use:

```
action="store_true"
```

```
import argparse


parser = argparse.ArgumentParser()

parser.add_argument(
    "--verbose",
    action="store_true",
    help="Show detailed output.",
)

args = parser.parse_args()

if args.verbose:
    print("Verbose mode enabled.")
else:
    print("Normal mode.")
```

Run normally:

```
python app.py
```

Output:

```
Normal mode.
```

Run with the flag:

```
python app.py --verbose
```

Output:

```
Verbose mode enabled.
```

The default is:

```
False
```

and it becomes:

```
True
```

when the flag appears.

## Another Boolean style

For a feature enabled by default but optionally disabled:

```
parser.add_argument(
    "--no-cache",
    action="store_true",
)
```

Then:

```
if args.no_cache:
    print("Caching disabled.")
```

Depending on your Python version and desired interface, `BooleanOptionalAction` can also create paired options such as `--cache` and `--no-cache`. For beginner CLI tools, `store_true` is usually enough.

# 12. Choices

Use `choices` when the value must come from a fixed set.

```
import argparse


parser = argparse.ArgumentParser()

parser.add_argument(
    "--priority",
    choices=["low", "normal", "high"],
    default="normal",
)

args = parser.parse_args()

print(f"Priority: {args.priority}")
```

Valid:

```
python ticket.py --priority high
```

Invalid:

```
python ticket.py --priority urgent
```

The parser displays the allowed choices:

```
invalid choice: 'urgent'
choose from 'low', 'normal', 'high'
```

This is better than manually writing:

```
if priority not in ["low", "normal", "high"]:
    ...
```

Use choices for:

- Modes
- Environments
- Formats
- Log levels
- Priorities
- Providers
- Output types
- Model strategies

Example:

```
parser.add_argument(
    "--format",
    choices=["json", "csv", "markdown"],
    default="json",
)
```

# 13. `dest`: controlling attribute names

By default:

```
parser.add_argument("--output-file")
```

creates:

```
args.output_file
```

You can explicitly define the attribute name:

```
parser.add_argument(
    "--output-file",
    dest="output_path",
)
```

Then use:

```
args.output_path
```

This can be useful when:

- The command-line spelling is awkward.
- Multiple options should map to one value.
- You need a clearer internal variable name.

Example:

```
parser.add_argument(
    "--model-name",
    dest="model",
)
```

```
print(args.model)
```

# 14. `metavar` and help formatting

`metavar` controls how a value appears in help.

```
parser.add_argument(
    "--output",
    metavar="PATH",
    help="Where to save the generated report.",
)
```

Help output may show:

```
--output PATH
```

instead of:

```
--output OUTPUT
```

For a positional argument:

```
parser.add_argument(
    "input_file",
    metavar="INPUT",
    help="Path to the input file.",
)
```

This makes help messages more readable.

# 15. `nargs`: accepting multiple values

`nargs` controls how many command-line values an argument accepts.

## One or more values

```
parser.add_argument(
    "files",
    nargs="+",
)
```

Run:

```
python combine.py a.txt b.txt c.txt
```

Then:

```
args.files
```

is:

```
["a.txt", "b.txt", "c.txt"]
```

## Zero or more values

```
parser.add_argument(
    "--tag",
    nargs="*",
)
```

This allows:

```
python app.py --tag ai python mlops
```

## Exactly two values

```
parser.add_argument(
    "--range",
    nargs=2,
    type=int,
)
```

Run:

```
python app.py --range 10 20
```

Then:

```
args.range == [10, 20]
```

## Optional single value

```
nargs="?"
```

Use this when an argument may have zero or one value, but be careful because it can make command syntax ambiguous.

# 16. Repeating options

Use:

```
action="append"
```

to allow an option multiple times.

```
parser.add_argument(
    "--tag",
    action="append",
)
```

Run:

```
python app.py \
    --tag ai \
    --tag python \
    --tag startup
```

Then:

```
args.tag
```

is:

```
["ai", "python", "startup"]
```

This is useful for:

- Multiple tags
- Multiple search paths
- Multiple filters
- Multiple configuration files
- Multiple plugin names

Another useful action is:

```
action="count"
```

Example:

```
parser.add_argument(
    "-v",
    "--verbose",
    action="count",
    default=0,
)
```

Run:

```
python app.py -vvv
```

Then:

```
args.verbose == 3
```

You can use levels:

```
if args.verbose >= 2:
    print("Very detailed output.")
```

# 17. Subcommands

A professional CLI often has subcommands:

```
trustdesk tickets list
trustdesk tickets add
trustdesk tickets delete
```

In Python:

```
import argparse


parser = argparse.ArgumentParser(
    prog="trustdesk",
    description="TrustDesk command-line tool.",
)

subparsers = parser.add_subparsers(
    dest="command",
    required=True,
)
```

Create a `tickets` subcommand:

```
tickets_parser = subparsers.add_parser(
    "tickets",
    help="Manage support tickets.",
)
```

Now add nested subcommands:

```
ticket_subparsers = tickets_parser.add_subparsers(
    dest="ticket_command",
    required=True,
)
```

Create `list`:

```
list_parser = ticket_subparsers.add_parser(
    "list",
    help="List support tickets.",
)
```

Create `add`:

```
add_parser = ticket_subparsers.add_parser(
    "add",
    help="Create a support ticket.",
)

add_parser.add_argument(
    "--title",
    required=True,
)

add_parser.add_argument(
    "--priority",
    choices=["low", "normal", "high"],
    default="normal",
)
```

Parse:

```
args = parser.parse_args()

print(args)
```

Run:

```
python trustdesk.py tickets add \
    --title "Cannot log in" \
    --priority high
```

Namespace will contain values similar to:

```
Namespace(
    command="tickets",
    ticket_command="add",
    title="Cannot log in",
    priority="high",
)
```

The `dest` argument on `add_subparsers()` stores the selected subcommand name. The official documentation uses this pattern for determining which subparser was invoked.[[docs.python](https://docs.python.org/3/library/argparse.html)]

# 18. Dispatching with `set_defaults`

Instead of writing a large chain of conditions:

```
if args.command == "tickets":
    if args.ticket_command == "list":
        ...
```

assign a function to each subcommand.

```
import argparse


def list_tickets(args):
    print("Listing tickets.")


def add_ticket(args):
    print(
        f"Adding ticket: {args.title} "
        f"({args.priority})"
    )
```

Build the parser:

```
parser = argparse.ArgumentParser(
    prog="trustdesk",
)

subparsers = parser.add_subparsers(
    dest="command",
    required=True,
)

tickets_parser = subparsers.add_parser(
    "tickets",
)

ticket_subparsers = tickets_parser.add_subparsers(
    dest="ticket_command",
    required=True,
)

list_parser = ticket_subparsers.add_parser(
    "list",
)

list_parser.set_defaults(function=list_tickets)

add_parser = ticket_subparsers.add_parser(
    "add",
)

add_parser.add_argument(
    "--title",
    required=True,
)

add_parser.add_argument(
    "--priority",
    choices=["low", "normal", "high"],
    default="normal",
)

add_parser.set_defaults(function=add_ticket)
```

Run the selected function:

```
args = parser.parse_args()
args.function(args)
```

Complete file:

```
import argparse


def list_tickets(args):
    print("Listing tickets.")


def add_ticket(args):
    print(
        f"Adding ticket: {args.title} "
        f"({args.priority})"
    )


def build_parser():
    parser = argparse.ArgumentParser(
        prog="trustdesk",
        description="TrustDesk command-line tool.",
    )

    subparsers = parser.add_subparsers(
        dest="command",
        required=True,
    )

    tickets_parser = subparsers.add_parser(
        "tickets",
        help="Manage support tickets.",
    )

    ticket_subparsers = tickets_parser.add_subparsers(
        dest="ticket_command",
        required=True,
    )

    list_parser = ticket_subparsers.add_parser(
        "list",
        help="List support tickets.",
    )

    list_parser.set_defaults(function=list_tickets)

    add_parser = ticket_subparsers.add_parser(
        "add",
        help="Create a support ticket.",
    )

    add_parser.add_argument(
        "--title",
        required=True,
        help="Ticket title.",
    )

    add_parser.add_argument(
        "--priority",
        choices=["low", "normal", "high"],
        default="normal",
        help="Ticket priority.",
    )

    add_parser.set_defaults(function=add_ticket)

    return parser


def main():
    parser = build_parser()
    args = parser.parse_args()
    args.function(args)


if __name__ == "__main__":
    main()
```

Run:

```
python trustdesk.py tickets list
```

Output:

```
Listing tickets.
```

Run:

```
python trustdesk.py tickets add \
    --title "Cannot log in" \
    --priority high
```

Output:

```
Adding ticket: Cannot log in (high)
```

This pattern scales much better than a large conditional statement.

# 19. The `main()` pattern

Use this structure for CLI programs:

```
def main():
    parser = build_parser()
    args = parser.parse_args()
    run_application(args)


if __name__ == "__main__":
    main()
```

Why?

## It prevents accidental execution during imports

If another file imports:

```
from app import build_parser
```

the CLI should not immediately run.

This condition:

```
if __name__ == "__main__":
```

runs `main()` only when the file is executed directly.

## It improves testing

You can test:

```
build_parser()
```

or:

```
main()
```

separately.

## It organizes responsibilities

A good structure is:

```
build_parser() → define CLI interface
main()          → parse arguments and dispatch
business logic  → perform actual work
```

# 20. Parsing custom argument lists

Normally:

```
args = parser.parse_args()
```

reads from `sys.argv`.

For testing, pass a list directly:

```
args = parser.parse_args([
    "tickets",
    "add",
    "--title",
    "Payment failed",
    "--priority",
    "high",
])
```

This is extremely useful in unit tests.

Example:

```
def test_add_command():
    parser = build_parser()

    args = parser.parse_args([
        "tickets",
        "add",
        "--title",
        "Payment failed",
        "--priority",
        "high",
    ])

    assert args.command == "tickets"
    assert args.ticket_command == "add"
    assert args.title == "Payment failed"
    assert args.priority == "high"
```

You can also use:

```
parser.parse_known_args()
```

when your program wants to parse known arguments while leaving unknown arguments for another system. Use this only when you intentionally need layered parsing.

# 21. `choices` with enums or conversion

You can combine `type` and `choices`.

```
parser.add_argument(
    "--port",
    type=int,
    choices=range(1, 65_536),
)
```

This accepts valid port numbers and rejects invalid ones.

A clearer custom validator may be better:

```
def port_number(value):
    try:
        port = int(value)
    except ValueError as error:
        raise argparse.ArgumentTypeError(
            "Port must be an integer."
        ) from error

    if not 1 <= port <= 65_535:
        raise argparse.ArgumentTypeError(
            "Port must be between 1 and 65535."
        )

    return port
```

```
parser.add_argument(
    "--port",
    type=port_number,
    default=8000,
)
```

# 22. Mutually exclusive options

Sometimes users should choose one option or another, but not both.

```
group = parser.add_mutually_exclusive_group()

group.add_argument(
    "--json",
    action="store_true",
)

group.add_argument(
    "--csv",
    action="store_true",
)
```

Valid:

```
python report.py --json
```

Valid:

```
python report.py --csv
```

Invalid:

```
python report.py --json --csv
```

The parser reports that the options are mutually exclusive.

You can make the group required:

```
group = parser.add_mutually_exclusive_group(
    required=True
)
```

Then the user must choose one.

This is useful for:

```
--production versus --development
--json versus --csv
--quiet versus --verbose
--include-closed versus --open-only
```

# 24. Parent parsers

If multiple subcommands share options, use a parent parser.

```
common_parser = argparse.ArgumentParser(
    add_help=False,
)

common_parser.add_argument(
    "--config",
    default="config.yaml",
    help="Configuration file.",
)
```

Use it when creating subparsers:

```
parser = argparse.ArgumentParser()

train_parser = parser.add_subparsers(
    dest="command",
    required=True,
)

train = train_parser.add_parser(
    "train",
    parents=[common_parser],
)

evaluate = train_parser.add_parser(
    "evaluate",
    parents=[common_parser],
)
```

Now both commands accept:

```
python ml.py train --config train.yaml
python ml.py evaluate --config eval.yaml
```

This avoids duplicating shared options.

# 25. Configuration files and environment variables

`argparse` handles command-line arguments, but real applications often combine three sources:

```
Defaults
    ↓
Configuration file
    ↓
Environment variables
    ↓
Command-line arguments
```

Command-line arguments usually have the highest priority.

A simple pattern:

```
import argparse
import os


parser = argparse.ArgumentParser()

parser.add_argument(
    "--model",
    default=os.getenv(
        "MODEL_NAME",
        "default-model",
    ),
)

args = parser.parse_args()

print(args.model)
```

Now:

```
MODEL_NAME=cloud-model python app.py
```

uses the environment value unless the user overrides it:

```
MODEL_NAME=cloud-model python app.py \
    --model local-model
```

Output:

```
local-model
```

For more complex configuration, parse the CLI separately and combine it with a configuration object.

# 26. A practical AI CLI

Let’s build a small command-line tool for classifying support tickets.

Run commands like:

```
python support_ai.py classify \
    --text "I cannot reset my password"
```

or:

```
python support_ai.py classify \
    --file tickets.txt \
    --format json
```

Complete example:

```
import argparse
import json
from pathlib import Path


def classify_text(text):
    normalized = text.lower()

    if "password" in normalized or "login" in normalized:
        return "account_access"

    if "payment" in normalized or "invoice" in normalized:
        return "billing"

    if "bug" in normalized or "error" in normalized:
        return "technical_issue"

    return "general"


def classify_command(args):
    if args.text is not None:
        text = args.text

    elif args.file is not None:
        text = Path(args.file).read_text(
            encoding="utf-8"
        )

    else:
        raise ValueError(
            "Provide either --text or --file."
        )

    category = classify_text(text)

    result = {
        "text": text,
        "category": category,
    }

    if args.format == "json":
        print(json.dumps(result, indent=2))
    else:
        print(
            f"Category: {category}\n"
            f"Text: {text}"
        )


def build_parser():
    parser = argparse.ArgumentParser(
        prog="support-ai",
        description=(
            "Classify customer-support messages."
        ),
    )

    subparsers = parser.add_subparsers(
        dest="command",
        required=True,
    )

    classify_parser = subparsers.add_parser(
        "classify",
        help="Classify a support message.",
    )

    source_group = (
        classify_parser.add_mutually_exclusive_group(
            required=True
        )
    )

    source_group.add_argument(
        "--text",
        help="Text to classify.",
    )

    source_group.add_argument(
        "--file",
        type=Path,
        help="File containing text to classify.",
    )

    classify_parser.add_argument(
        "--format",
        choices=["text", "json"],
        default="text",
        help="Output format.",
    )

    classify_parser.set_defaults(
        function=classify_command
    )

    return parser


def main():
    parser = build_parser()
    args = parser.parse_args()
    args.function(args)


if __name__ == "__main__":
    main()
```

Run:

```
python support_ai.py classify \
    --text "My payment failed" \
    --format json
```

Output:

```
{
  "text": "My payment failed",
  "category": "billing"
}
```

Run help:

```
python support_ai.py --help
```

Run subcommand help:

```
python support_ai.py classify --help
```

This example combines:

- A top-level parser
- A subcommand
- Mutually exclusive input sources
- `pathlib.Path`
- Choices

- JSON output

- A clean `main()` entry point

# 27. `argparse.FileType`

For simple file handling, `argparse.FileType` can open the file for you.

```
import argparse


parser = argparse.ArgumentParser()

parser.add_argument(
    "--input",
    type=argparse.FileType(
        "r",
        encoding="utf-8",
    ),
)

args = parser.parse_args()

if args.input:
    content = args.input.read()
    print(content)
```

Run:

```
python app.py --input notes.txt
```

For output:

```
parser.add_argument(
    "--output",
    type=argparse.FileType(
        "w",
        encoding="utf-8",
    ),
)
```

Then:

```
if args.output:
    args.output.write("Generated output.\n")
```

## Important caution

When you use `argparse.FileType`, the file is opened during argument parsing. For complex programs, using `pathlib.Path` and opening the file inside your command function often gives you more control over:

- Error handling
- Resource lifetime
- Encoding
- Validation
- Transactions
- Multiple operations

For beginners and production applications, this is often clearer:

```
parser.add_argument(
    "--input",
    type=Path,
)
```

Then:

```
text = args.input.read_text(encoding="utf-8")
```

# 28. Error handling

`argparse` automatically handles many command-line errors:

```
python app.py --unknown-option
```

```
error: unrecognized arguments: --unknown-option
```

Missing required argument:

```
python app.py
```

```
error: the following arguments are required: name
```

Invalid choice:

```
python ticket.py --priority urgent
```

```
error: argument --priority: invalid choice: 'urgent'
```

Usually, allow `argparse` to display these errors. Do not wrap the entire parser in:

```
try:
    ...
except Exception:
    print("Something went wrong.")
```

That can hide useful parser messages.

# 29. Testing CLI programs

Testing is easier when parsing and business logic are separate.

```
def classify_command(args):
    ...
```

Test the business function independently:

```
def test_classify_billing_message():
    assert classify_text(
        "My invoice is incorrect"
    ) == "billing"
```

Test parser behavior with a list:

```
def test_classify_parser():
    parser = build_parser()

    args = parser.parse_args([
        "classify",
        "--text",
        "I cannot log in",
        "--format",
        "json",
    ])

    assert args.command == "classify"
    assert args.text == "I cannot log in"
    assert args.format == "json"
```

A high-quality CLI usually has three test layers:

```
Parser tests       → Are arguments interpreted correctly?
Business tests     → Does the application logic work?
Integration tests  → Does the complete command work?
```

# 30. `parse_args()` and `sys.argv`

This:

```
args = parser.parse_args()
```

reads:

```
sys.argv[1:]
```

This:

```
args = parser.parse_args(["--verbose"])
```

parses the list you provide instead.

You can inspect the result:

```
print(vars(args))
```

Example:

```
Namespace(name="Toussaint", verbose=True)
```

becomes:

```
{
    "name": "Toussaint",
    "verbose": True,
}
```

You can also create a pre-populated namespace:

```
namespace = argparse.Namespace(
    name="Default User"
)

args = parser.parse_args(
    namespace=namespace
)
```

This is less common for beginner applications but can be useful when combining configuration sources.

# 31. Better CLI architecture

For a growing CLI, use this structure:

```
project/
├── pyproject.toml
├── src/
│   └── trustdesk_cli/
│       ├── __init__.py
│       ├── __main__.py
│       ├── cli.py
│       ├── commands/
│       │   ├── tickets.py
│       │   └── users.py
│       └── services/
│           ├── classifier.py
│           └── repository.py
└── tests/
    ├── test_cli.py
    └── test_classifier.py
```

Keep responsibilities separate:

```
cli.py                  → parser and dispatch
commands/tickets.py     → ticket command handlers
services/classifier.py  → AI classification logic
services/repository.py  → persistence
tests/                  → automated tests
```

Avoid putting all business logic inside:

```
main()
```

A good CLI is a user interface layer—not the entire application.

# 32. Common mistakes

## Forgetting `type=int`

Incorrect:

```
parser.add_argument("--limit")
```

Then:

```
args.limit + 1
```

may fail or concatenate strings.

Correct:

```
parser.add_argument(
    "--limit",
    type=int,
)
```

---

## Using `type=bool`

Avoid:

```
parser.add_argument(
    "--debug",
    type=bool,
)
```

This behaves unexpectedly because:

```
bool("false") == True
```

Use:

```
parser.add_argument(
    "--debug",
    action="store_true",
)
```

---

## Using `default=[]`

Avoid:

```
parser.add_argument(
    "--tags",
    default=[],
)
```

While this is not exactly the same mutable-default issue as function definitions, it is clearer to use:

```
action="append"
```

or:

```
default=None
```

Then normalize later:

```
tags = args.tags or []
```

---

## Forgetting `required=True` for subcommands

Without:

```
required=True
```

the user may run:

```
python app.py
```

without choosing a command, leaving:

```
args.command is None
```

For modern Python versions, use:

```
subparsers = parser.add_subparsers(
    dest="command",
    required=True,
)
```

If supporting older Python versions, manually validate the result.

---

## Hiding business logic in parser construction

Avoid:

```
parser.add_argument(
    "--model",
    default=load_model_from_database(),
)
```

This loads the model while merely constructing the parser.

Prefer:

```
parser.add_argument(
    "--model",
    default="default-model",
)
```

Then load it inside the command function.

---

## Creating a giant `if` chain

Avoid:

```
if args.command == "a":
    ...
elif args.command == "b":
    ...
elif args.command == "c":
    ...
```

For a small tool, this is fine. For a growing CLI, use:

```
subparser.set_defaults(function=handler)
```

and:

```
args.function(args)
```

# 34. Final cheat sheet

## Basic parser

```
parser = argparse.ArgumentParser(

```
parser.add_argument(

```
parser.add_argument(

```
parser.add_argument(

    type=int,

```

```
parser.add_argument(
    "--verbose",
    action="store_true",
)
```

```
parser.add_argument(

    default="json",

```
parser.add_argument(
    "--tag",
    action="append",
)

```
group = parser.add_mutually_exclusive_group(
    required=True

group.add_argument("--text")

## Subcommand

```
subparsers = parser.add_subparsers(

```

## Dispatch handler

```
subparser.set_defaults(function=handler)
```

```
args = parser.parse_args()
args.function(args)
```

```
Define the command interface.
