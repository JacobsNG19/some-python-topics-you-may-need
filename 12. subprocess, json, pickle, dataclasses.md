These four tools solve different problems:

- `subprocess`: run external programs.
- `json`: exchange data safely across languages and systems.
- `pickle`: serialize Python objects, but only when the data is trusted.
- `dataclasses`: reduce boilerplate when creating data-focused classes.

# 1. `subprocess`

The `subprocess` module lets Python start another process, provide input, capture output, and inspect the exit code. The modern default for simple commands is `subprocess.run()`.[[docs.python](https://docs.python.org/3/library/subprocess.html)]

## Basic command

```
import subprocess


result = subprocess.run(
    ["python", "--version"],
    capture_output=True,
    text=True,
)

print(result.stdout)
print(result.returncode)
```

The command is passed as a list:

```
["python", "--version"]
```

This is safer and clearer than constructing one shell command string.

## Important `CompletedProcess` attributes

```
result.args          # Command that was executed
result.stdout        # Captured standard output
result.stderr        # Captured standard error
result.returncode    # Exit status
```

Example:

```
result = subprocess.run(
    ["python", "-c", "print('Hello from child process')"],
    capture_output=True,
    text=True,
)

print(result.stdout)
print(result.stderr)
print(result.returncode)
```

Possible output:

```
Hello from child process

0
```

A return code of:

```
0
```

normally means success.

A non-zero return code usually means failure.

---

## `capture_output=True`

Without capture:

```
subprocess.run(["python", "--version"])
```

the child process writes directly to the terminal.

With:

```
result = subprocess.run(
    ["python", "--version"],
    capture_output=True,
    text=True,
)
```

Python stores output in:

```
result.stdout
result.stderr
```

The `text=True` option decodes output into strings. Without it, captured output is returned as bytes.

Equivalent explicit form:

```
result = subprocess.run(
    ["python", "--version"],
    stdout=subprocess.PIPE,
    stderr=subprocess.PIPE,
    text=True,
)
```

Usually prefer:

```
capture_output=True
```

for simple cases.[[docs.python](https://docs.python.org/3/library/subprocess.html)]

---

## `check=True`

By default, a failed command does not automatically raise an exception:

```
result = subprocess.run(
    ["python", "-c", "raise SystemExit(1)"],
    capture_output=True,
    text=True,
)

print(result.returncode)
```

Output:

```
1
```

Use:

```
check=True
```

when failure should raise `CalledProcessError`.

```
try:
    subprocess.run(
        ["python", "-c", "raise SystemExit(1)"],
        check=True,
    )

except subprocess.CalledProcessError as error:
    print(f"Command failed with code {error.returncode}.")
```

For most commands that your application depends on, use:

```
check=True
```

Example:

```
subprocess.run(
    ["git", "status"],
    check=True,
)
```

The official documentation recommends `run(..., check=True)` for raising an exception when a command returns a non-zero exit status.[[docs.python](https://docs.python.org/3/library/subprocess.html)]

---

## `timeout`

Prevent a command from running forever:

```
import subprocess


try:
    result = subprocess.run(
        ["python", "-c", "import time; time.sleep(10)"],
        timeout=2,
        capture_output=True,
        text=True,
        check=True,
    )

except subprocess.TimeoutExpired:
    print("The command timed out.")
```

Use timeouts for:

- External model tools.
- CLI utilities.
- Network-related processes.
- Data-processing commands.
- User-provided scripts.
- Long-running builds.

A timeout is not optional when calling an unreliable external program.

---

## `cwd`

Run the command from a specific working directory:

```
from pathlib import Path
import subprocess


project_dir = Path("/path/to/project")

result = subprocess.run(
    ["git", "status"],
    cwd=project_dir,
    capture_output=True,
    text=True,
    check=True,
)
```

This avoids changing Python’s own working directory globally.

---

## `env`

Provide environment variables:

```
import os
import subprocess


environment = os.environ.copy()
environment["APP_MODE"] = "testing"

result = subprocess.run(
    ["python", "app.py"],
    env=environment,
    capture_output=True,
    text=True,
)
```

Use `os.environ.copy()` so you preserve existing environment variables.

---

## Input through standard input

```
import subprocess


result = subprocess.run(
    ["python", "-c", "print(input().upper())"],
    input="hello from parent process\n",
    capture_output=True,
    text=True,
    check=True,
)

print(result.stdout)
```

Output:

```
HELLO FROM PARENT PROCESS
```

---

## `shell=True` security warning

Avoid this when command input contains user-controlled data:

```
filename = user_input

subprocess.run(
    f"cat {filename}",
    shell=True,
)
```

# 1. `subprocess`: running external programs

The `subprocess` module lets Python start another process, connect to its input/output/error streams, and inspect its return code.[[docs.python](https://docs.python.org/3/library/subprocess.html)]

For example, run Python itself:

```
import subprocess


result = subprocess.run(
    ["python", "--version"],
    capture_output=True,
    text=True,
)

print(result.stdout)
print(result.returncode)
```

Possible output:

```
Python 3.14.7
0
```

## Important `CompletedProcess` attributes

`subprocess.run()` returns a `CompletedProcess` object.

```
result.args         # Command that was executed
result.returncode   # Exit code
result.stdout       # Captured standard output
result.stderr       # Captured standard error
```

A return code of:

```
0
```

usually means success.

A non-zero code usually indicates failure.

---

## Running a command

```
import subprocess


subprocess.run(
    ["echo", "Hello from Python"],
)
```

On many systems, output appears directly in the terminal.

Use a list of arguments:

```
subprocess.run([
    "git",
    "status",
])
```

This is safer and clearer than constructing one large shell string.

---

## Capturing output

```
result = subprocess.run(
    ["python", "--version"],
    capture_output=True,
    text=True,
)

print("Output:", result.stdout)
print("Errors:", result.stderr)
```

`capture_output=True` captures both standard output and standard error. The `text=True` option returns strings instead of raw bytes.[[docs.python](https://docs.python.org/3/library/subprocess.html)]

Equivalent lower-level configuration:

```
result = subprocess.run(
    ["python", "--version"],
    stdout=subprocess.PIPE,
    stderr=subprocess.PIPE,
    text=True,
)
```

Usually prefer:

```
capture_output=True
```

because it is shorter.

---

## `check=True`

By default, a failed command does not automatically raise an exception.

```
result = subprocess.run(
    ["python", "missing_file.py"],
    capture_output=True,
    text=True,
)

print(result.returncode)
```

With:

```
check=True
```

Python raises `subprocess.CalledProcessError` if the command returns a non-zero exit code.

```
import subprocess


try:
    subprocess.run(
        ["python", "missing_file.py"],
        check=True,
    )

except subprocess.CalledProcessError as error:
    print(f"Command failed with code {error.returncode}.")
```

Use `check=True` when failure should stop the current operation.

```
subprocess.run(
    ["git", "status"],
    check=True,
)
```

---

## `cwd`: working directory

Run a command from a specific directory:

```
result = subprocess.run(
    ["git", "status"],
    cwd="/path/to/project",
    capture_output=True,
    text=True,
    check=True,
)
```

Using `pathlib` is often better:

```
from pathlib import Path
import subprocess


project_dir = Path("my_project")

subprocess.run(
    ["git", "status"],
    cwd=project_dir,
    check=True,
)
```

---

## Environment variables

Pass a custom environment:

```
import os
import subprocess


environment = os.environ.copy()
environment["MODEL_MODE"] = "testing"

result = subprocess.run(
    ["python", "show_mode.py"],
    env=environment,
    capture_output=True,
    text=True,
)
```

Do not accidentally replace the entire environment unless that is intentional:

```
# Potentially dangerous: may remove PATH and other variables
env={"MODEL_MODE": "testing"}
```

Usually start with:

```
os.environ.copy()
```

and modify the copy.

---

## Timeouts

Prevent a command from waiting forever:

```
import subprocess


try:
    result = subprocess.run(
        ["python", "long_task.py"],
        timeout=10,
        capture_output=True,
        text=True,
        check=True,
    )

except subprocess.TimeoutExpired:
    print("The command took too long.")
```

A timeout is especially useful when calling:

- External CLI tools
- Model servers
- Shell utilities
- Build processes
- Data-processing scripts
- Network-related command-line programs

---

## `shell=True`: security warning

Avoid:

```
subprocess.run(
    user_input,
    shell=True,
)
```

If `user_input` contains malicious shell syntax, it may execute unintended commands.

Dangerous example:

```
user_input = "file.txt; rm -rf important_data"

subprocess.run(
    f"cat {user_input}",
    shell=True,
)
```

Prefer:

```
subprocess.run([
    "cat",
    user_input,
])
```

The list form avoids asking a shell to interpret the command.

Use `shell=True` only when you genuinely need shell features and the command is fully trusted or carefully validated. Python’s documentation specifically warns that shell invocation can introduce security considerations when handling untrusted input.[[docs.python](https://docs.python.org/3/library/subprocess.html)]

---

## Sending input

You can send input to a process:

```
result = subprocess.run(
    ["python", "-c", "print(input().upper())"],
    input="hello",
    capture_output=True,
    text=True,
)

print(result.stdout)
```

Output:

```
HELLO
```

For multiple lines:

```
result = subprocess.run(
    ["sort"],
    input="banana\napple\ncherry\n",
    capture_output=True,
    text=True,
)

print(result.stdout)
```

Output:

```
apple
banana
cherry
```

---

## `Popen`: advanced process control

`subprocess.run()` waits until the process finishes.

Use `subprocess.Popen` when you need more control:

```
import subprocess


process = subprocess.Popen(
    ["python", "worker.py"],
    stdout=subprocess.PIPE,
    stderr=subprocess.PIPE,
    text=True,
)

stdout, stderr = process.communicate()

print(stdout)
print(stderr)
print(process.returncode)
```

`Popen` is useful for:

- Long-running processes
- Streaming output
- Interactive processes
- Process pipelines
- Starting background services
- Communicating incrementally

For most commands, use:

```
subprocess.run(...)
```

For advanced lifecycle control, use:

```
subprocess.Popen(...)
```

---

## A typed command helper

```
from dataclasses import dataclass
import subprocess


@dataclass
class CommandResult:
    command: list[str]
    output: str
    error: str
    returncode: int


def run_command(command: list[str]) -> CommandResult:
    result = subprocess.run(
        command,
        capture_output=True,
        text=True,
    )

    return CommandResult(
        command=command,
        output=result.stdout,
        error=result.stderr,
        returncode=result.returncode,
    )
```

Use it:

```
result = run_command([
    "python",
    "--version",
])

print(result.output)
print(result.returncode)
```

This combines `subprocess` and `dataclasses`.

# 2. `json`: portable structured data

JSON is a lightweight data-interchange format based on object and array structures. Python’s `json` module converts between Python values and JSON text.[[docs.python](https://docs.python.org/3/library/json.html)]

## Python to JSON

Use:

```
json.dumps()
```

```
import json


ticket = {
    "id": "T-001",
    "title": "Cannot log in",
    "priority": "high",
}

json_text = json.dumps(ticket)

print(json_text)
```

Output:

```
{"id": "T-001", "title": "Cannot log in", "priority": "high"}
```

`dumps` means:

```
dump to string
```

## Pretty JSON

```
json_text = json.dumps(
    ticket,
    indent=2,
)

print(json_text)
```

Output:

```
{
  "id": "T-001",
  "title": "Cannot log in",
  "priority": "high"
}
```

Useful options:

```
json.dumps(
    data,
    indent=2,
    sort_keys=True,
    ensure_ascii=False,
)
```

- `indent=2` makes it readable.
- `sort_keys=True` sorts dictionary keys.
- `ensure_ascii=False` preserves non-ASCII characters.

---

## JSON to Python

Use:

```
json.loads()
```

```
json_text = """
{
  "id": "T-001",
  "priority": "high"
}
"""

ticket = json.loads(json_text)

print(ticket)
print(ticket["priority"])
```

Output:

```
{'id': 'T-001', 'priority': 'high'}
high
```

`loads` means:

```
load from string
```

---

## JSON files

Use:

```
json.dump()
```

to write JSON to a file:

```
import json


settings = {
    "model": "ticket-classifier-v1",
    "temperature": 0.2,
    "debug": True,
}

with open(
    "settings.json",
    "w",
    encoding="utf-8",
) as file:
    json.dump(
        settings,
        file,
        indent=2,
    )
```

Use:

```
json.load()
```

to read it:

```
with open(
    "settings.json",
    "r",
    encoding="utf-8",
) as file:
    settings = json.load(file)

print(settings["model"])
```

The difference is:

|Function|Direction|Destination/source|
|---|---|---|
|`dumps`|Python → JSON|String|
|`loads`|JSON → Python|String|
|`dump`|Python → JSON|File-like object|
|`load`|JSON → Python|File-like object|

The JSON documentation defines these four functions as the main serialization and deserialization interfaces.[[docs.python](https://docs.python.org/3/library/json.html)]

---

## JSON-supported Python types

|Python|JSON|
|---|---|
|`dict`|object|
|`list`, `tuple`|array|
|`str`|string|
|`int`, `float`|number|
|`True`|`true`|
|`False`|`false`|
|`None`|`null`|

Example:

```
data = {
    "name": "Toussaint",
    "age": 20,
    "active": True,
    "skills": ["Python", "SQL"],
    "bio": None,
}
```

```
print(json.dumps(data, indent=2))
```

---

## JSON limitations

This fails:

```
from datetime import datetime
import json


data = {
    "created_at": datetime.now(),
}

json.dumps(data)
```

A `datetime` is not directly JSON serializable.

You can convert it manually:

```
data = {
    "created_at": datetime.now().isoformat(),
}
```

Or provide a custom serializer:

```
from datetime import datetime
import json


def serialize(value):
    if isinstance(value, datetime):
        return value.isoformat()

    raise TypeError(
        f"Unsupported type: {type(value).__name__}"
    )
```

```
data = {
    "created_at": datetime.now(),
}

json_text = json.dumps(
    data,
    default=serialize,
)

print(json_text)
```

Other values requiring special handling include:

- `set`
- `bytes`
- Custom classes
- Decimal values
- Dates and times
- NumPy arrays
- Model objects

---

## `object_hook`

`object_hook` lets you transform decoded dictionaries.

```
import json


def convert_ticket(data):
    if data.get("type") == "ticket":
        return Ticket(
            ticket_id=data["id"],
            title=data["title"],
        )

    return data
```

```
decoded = json.loads(
    json_text,
    object_hook=convert_ticket,
)
```

This is advanced and often less clear than explicitly converting data after loading.

---

## JSON validation

You can validate JSON from the command line:

```
python -m json.tool data.json
```

On current Python versions, the `json` module can also be invoked directly as a command-line tool for validation and pretty-printing.[[docs.python](https://docs.python.org/3/library/json.html)]

# 3. `pickle`: Python-specific serialization

`pickle` converts Python object structures into a binary byte stream and restores them later.[[docs.python](https://docs.python.org/3/library/pickle.html)]

## Basic usage

```
import pickle


data = {
    "name": "Toussaint",
    "scores": [0.9, 0.95],
}

with open("data.pkl", "wb") as file:
    pickle.dump(data, file)
```

Read it:

```
with open("data.pkl", "rb") as file:
    loaded_data = pickle.load(file)

print(loaded_data)
```

Important file modes:

```
"wb" → write binary
"rb" → read binary
```

## `dumps` and `loads`

```
binary_data = pickle.dumps(data)
restored_data = pickle.loads(binary_data)
```

Unlike JSON, pickle can preserve many Python-specific objects:

- Tuples
- Sets
- Custom class instances
- Some functions
- Some class structures
- Complex nested Python objects

---

## Critical security warning

Never unpickle untrusted data.

```
pickle.load(file)
```

can execute arbitrary code embedded in a malicious pickle file. The official documentation explicitly states that pickle is not secure and that unpickling untrusted or tampered data can execute arbitrary code.[[docs.python](https://docs.python.org/3/library/pickle.html)]

Unsafe sources include:

- User uploads
- Email attachments
- Public downloads
- Unverified GitHub files
- HTTP responses
- Shared folders
- Files from unknown collaborators
- Model artifacts without integrity verification

The rule is:

```
Only unpickle data you completely trust.
```

JSON is safer for untrusted data, although JSON still requires validation because malicious or unexpected content can cause application-level problems.

---

## Pickle and machine-learning models

Pickle is historically used for Python and ML objects:

```
with open("model.pkl", "wb") as file:
    pickle.dump(model, file)
```

But loading arbitrary model files is dangerous.

For production model artifacts:

- Use trusted sources.
- Verify file integrity.
- Restrict filesystem permissions.
- Store artifacts in controlled registries.
- Consider safer model formats where appropriate.
- Do not load files directly from user input.
- Separate model-serving processes when risk is high.

For scikit-learn objects, `joblib` is also common, but it has similar trust concerns when loading serialized Python objects. Serialization is not automatically safe merely because the file extension looks like a model.

---

## JSON versus pickle

|Feature|JSON|Pickle|
|---|---|---|
|Human-readable|Yes|No|
|Language-independent|Yes|Mostly Python-specific|
|Safe against code execution on load|Much safer, still validate data|No|
|Preserves custom Python objects|No, not directly|Yes|
|Good for APIs|Excellent|Poor|
|Good for configuration|Excellent|Poor|
|Good for simple interchange|Excellent|Poor|
|Good for trusted Python caches|Sometimes|Sometimes|
|Works with arbitrary Python structures|Limited|Broad|

Use:

```
JSON → APIs, configuration, public data, interoperability
Pickle → trusted Python-only internal objects and temporary caches
```

Never use pickle as a general replacement for JSON.

# 4. `dataclasses`: structured classes

A dataclass is a normal Python class enhanced by the `@dataclass` decorator. It can automatically generate methods such as `__init__()` and `__repr__()` from annotated fields.[[docs.python](https://docs.python.org/3/library/dataclasses.html)]

## Basic dataclass

```
from dataclasses import dataclass


@dataclass
class Ticket:
    ticket_id: str
    title: str
    priority: str
```

Create an object:

```
ticket = Ticket(
    ticket_id="T-001",
    title="Cannot log in",
    priority="high",
)
```

Print it:

```
print(ticket)
```

Output:

```
Ticket(ticket_id='T-001', title='Cannot log in', priority='high')
```

Without `@dataclass`, you would write the constructor and representation manually.

The class still behaves like a normal Python class:

```
print(ticket.title)
ticket.priority = "normal"
```

---

## Dataclass fields and defaults

```
@dataclass
class User:
    username: str
    email: str
    active: bool = True
```

Usage:

```
user = User(
    username="toussaint",
    email="toussaint@example.com",
)

print(user)
```

Output:

```
User(username='toussaint', email='toussaint@example.com', active=True)
```

Fields without defaults must come before fields with defaults:

```
# Correct
@dataclass
class Example:
    required_value: str
    optional_value: int = 0
```

This is invalid:

```
# Incorrect
@dataclass
class Example:
    optional_value: int = 0
    required_value: str
```

---

## `field(default_factory=...)`

Never use a mutable object directly as a default:

```
# Wrong
@dataclass
class Project:
    tasks: list[str] = []
```

Use:

```
from dataclasses import dataclass, field
```

```
@dataclass
class Project:
    name: str
    tasks: list[str] = field(
        default_factory=list
    )
```

Now each project gets a separate list:

```
project_a = Project("TrustDesk")
project_b = Project("Burvex")

project_a.tasks.append("Build MVP")

print(project_a.tasks)
print(project_b.tasks)
```

Output:

```
['Build MVP']
[]
```

`default_factory=list` calls `list()` separately for each instance.

Other examples:

```
metadata: dict[str, str] = field(
    default_factory=dict
)
```

```
tags: set[str] = field(
    default_factory=set
)
```

---

## Dataclass methods

Dataclasses can generate:

```
__init__
__repr__
__eq__
```

by default.

```
@dataclass
class Point:
    x: int
    y: int
```

```
point_a = Point(1, 2)
point_b = Point(1, 2)

print(point_a == point_b)
```

Output:

```
True
```

Because dataclasses compare fields by value by default.

---

## Frozen dataclasses

Use:

```
frozen=True
```

to prevent normal attribute assignment after creation.

```
@dataclass(frozen=True)
class Coordinates:
    latitude: float
    longitude: float
```

```
location = Coordinates(3.38, 29.36)

location.latitude = 4.0
```

This raises:

```
dataclasses.FrozenInstanceError
```

Frozen dataclasses are useful for value-like objects and configuration that should not change.

They are not an absolute security boundary. Python internals can sometimes bypass normal restrictions, and nested mutable values may remain mutable.

---

## Dataclass field options

```
@dataclass
class User:
    username: str
    email: str = field(
        repr=False
    )
```

Now:

```
user = User(
    username="toussaint",
    email="private@example.com",
)

print(user)
```

The email is excluded from the generated representation.

Useful options:

```
field(
    default=value,
    default_factory=function,
    init=False,
    repr=False,
    compare=False,
    kw_only=True,
)
```

## `init=False`

```
@dataclass
class Rectangle:
    width: float
    height: float
    area: float = field(init=False)

    def __post_init__(self):
        self.area = self.width * self.height
```

```
rectangle = Rectangle(10, 5)

print(rectangle.area)
```

Output:

```
50
```

`area` is calculated internally and is not accepted as a constructor argument.

## `compare=False`

```
@dataclass
class Request:
    request_id: str = field(
        compare=False
    )
    payload: str
```

Two requests with the same payload can compare equal even if their request IDs differ.

Use this carefully; equality should reflect your domain’s meaning.

---

## `__post_init__`

Use `__post_init__()` for validation or derived fields.

```
@dataclass
class Product:
    name: str
    price: float

    def __post_init__(self):
        self.name = self.name.strip()

        if not self.name:
            raise ValueError(
                "Product name cannot be empty."
            )

        if self.price < 0:
            raise ValueError(
                "Price cannot be negative."
            )
```

Usage:

```
product = Product(
    name="  AI Subscription  ",
    price=29.99,
)

print(product)
```

Output:

```
Product(name='AI Subscription', price=29.99)
```

Invalid input:

```
Product("", 10)
```

raises:

```
ValueError
```

Dataclass annotations describe fields, but the decorator generally does not validate the annotated types at runtime.[[docs.python](https://docs.python.org/3/library/dataclasses.html)]

---

## Dataclasses and methods

A dataclass can contain normal methods.

```
@dataclass
class Budget:
    total: float
    spent: float = 0.0

    @property
    def remaining(self) -> float:
        return self.total - self.spent

    def add_expense(self, amount: float) -> None:
        if amount <= 0:
            raise ValueError(
                "Expense must be positive."
            )

        if amount > self.remaining:
            raise ValueError(
                "Expense exceeds remaining budget."
            )

        self.spent += amount
```

Use:

```
budget = Budget(total=5_000)

budget.add_expense(500)

print(budget.remaining)
```

Output:

```
4500.0
```

This is a good domain model because the data and rules live together.

# 5. Dataclasses and JSON

Dataclasses do not automatically become JSON.

```
import json
from dataclasses import asdict, dataclass
```

```
@dataclass
class Ticket:
    ticket_id: str
    title: str
    priority: str
```

Convert to a dictionary:

```
ticket = Ticket(
    "T-001",
    "Cannot log in",
    "high",
)

ticket_dict = asdict(ticket)

print(ticket_dict)
```

Output:

```
{
    "ticket_id": "T-001",
    "title": "Cannot log in",
    "priority": "high",
}
```

Convert to JSON:

```
json_text = json.dumps(
    asdict(ticket),
    indent=2,
)

print(json_text)
```

## Reconstructing a dataclass

```
data = json.loads(json_text)

restored_ticket = Ticket(**data)

print(restored_ticket)
```

This works if the JSON dictionary keys match the dataclass constructor fields.

## Important security note

Do not blindly pass arbitrary external dictionaries into constructors:

```
Ticket(**untrusted_data)
```

Validate first:

```
required_keys = {
    "ticket_id",
    "title",
    "priority",
}

if not required_keys.issubset(data):
    raise ValueError("Invalid ticket data.")
```

For complex or untrusted API data, use explicit validation.

# 6. Dataclasses and `TypedDict`

You learned `TypedDict` previously.

Use `TypedDict` for dictionary-shaped data:

```
class TicketData(TypedDict):
    id: str
    title: str
    priority: Literal[
        "low",
        "normal",
        "high",
    ]
```

Use a dataclass for a domain object:

```
@dataclass
class Ticket:
    id: str
    title: str
    priority: str

    def close(self):
        ...
```

Comparison:

```
TypedDict → API payload or JSON-shaped dictionary
dataclass → object with attributes, methods, and behavior
```

A common architecture is:

```
raw JSON
   ↓
validate into TypedDict or schema
   ↓
construct dataclass
   ↓
run business methods
```

# 7. Dataclasses and pickle

Dataclass instances can often be pickled:

```
import pickle
from dataclasses import dataclass
```

```
@dataclass
class ModelConfig:
    model_name: str
    temperature: float
```

```
config = ModelConfig(
    model_name="ticket-classifier-v1",
    temperature=0.2,
)

with open("config.pkl", "wb") as file:
    pickle.dump(config, file)
```

Read it only from a trusted source:

```
with open("config.pkl", "rb") as file:
    restored = pickle.load(file)
```

Remember:

```
Dataclass → clean object model
Pickle → binary Python serialization
```

The combination is convenient but inherits pickle’s security risk. Never load an untrusted dataclass pickle.[[docs.python](https://docs.python.org/3/library/pickle.html)]

For configuration, JSON is usually better:

```
config = {
    "model_name": "ticket-classifier-v1",
    "temperature": 0.2,
}
```

# 8. Combined project example

Let’s build a small typed ticket runner that:

1. Uses a dataclass for a ticket.
2. Writes ticket data as JSON.
3. Runs an external command with `subprocess`.
4. Uses logging.
5. Avoids pickle for untrusted interchange.

```
from dataclasses import asdict, dataclass
import json
import subprocess
from pathlib import Path
```

Define the domain object:

```
@dataclass
class Ticket:
    ticket_id: str
    title: str
    priority: str

    def __post_init__(self):
        self.title = self.title.strip()

        if not self.title:
            raise ValueError(
                "Ticket title cannot be empty."
            )

        if self.priority not in {
            "low",
            "normal",
            "high",
        }:
            raise ValueError(
                "Invalid ticket priority."
            )
```

Save as JSON:

```
def save_ticket(
    ticket: Ticket,
    path: Path,
) -> None:
    with path.open(
        "w",
        encoding="utf-8",
    ) as file:
        json.dump(
            asdict(ticket),
            file,
            indent=2,
        )
```

Run an external command:

```
def get_python_version() -> str:
    result = subprocess.run(
        ["python", "--version"],
        capture_output=True,
        text=True,
        check=True,
    )

    output = result.stdout or result.stderr

    return output.strip()
```

Use everything:

```
def main():
    ticket = Ticket(
        ticket_id="T-001",
        title=" Cannot log in ",
        priority="high",
    )

    save_ticket(
        ticket,
        Path("ticket.json"),
    )

    print(ticket)
    print(get_python_version())


if __name__ == "__main__":
    main()
```

Possible output:

```
Ticket(ticket_id='T-001', title='Cannot log in', priority='high')
Python 3.14.7
```

Generated JSON:

```
{
  "ticket_id": "T-001",
  "title": "Cannot log in",
  "priority": "high"
}
```

This is a realistic combination for a small automation or AI-engineering utility.

# 9. Choosing the right tool

|Need|Use|
|---|---|
|Run another program|`subprocess.run()`|
|Control a long-running process|`subprocess.Popen()`|
|Exchange data with APIs|`json`|
|Store readable configuration|`json`|
|Store trusted Python-only objects|`pickle`, cautiously|
|Represent structured domain data|`dataclass`|
|Describe JSON dictionary shape statically|`TypedDict`|
|Validate external data at runtime|Manual validation or a validation library|

## Typical AI project decisions

```
CLI calls model-evaluation script → subprocess
API request/response              → JSON
Model configuration file           → JSON
Trusted temporary Python cache     → pickle, cautiously
Ticket/model-result object         → dataclass
External response type description → TypedDict
```

# 10. Common mistakes

## Using `shell=True` with user input

```
subprocess.run(
    f"tool {user_input}",
    shell=True,
)
```

Prefer:

```
subprocess.run([
    "tool",
    user_input,
])
```

---

## Forgetting `text=True`

Without it, captured output is bytes:

```
result.stdout == b"some output"
```

With it:

```
result.stdout == "some output"
```

---

## Ignoring failed subprocess commands

```
subprocess.run(command)
```

may continue even when the command fails.

Use:

```
subprocess.run(
    command,
    check=True,
)
```

when failure should raise an exception.

---

## Using `pickle.load()` on external data

Never:

```
pickle.load(uploaded_file)
```

unless the source is completely trusted.

---

## Expecting JSON to serialize custom objects

This fails:

```
json.dumps(ticket)
```

Use:

```
json.dumps(asdict(ticket))
```

for a dataclass.

---

## Mutable dataclass defaults

Wrong:

```
@dataclass
class Project:
    tasks: list[str] = []
```

Correct:

```
@dataclass
class Project:
    tasks: list[str] = field(
        default_factory=list
    )
```

---

## Assuming dataclass annotations validate values

This does not necessarily reject invalid runtime data:

```
@dataclass
class User:
    age: int

user = User(age="twenty")
```

Add validation:

```
def __post_init__(self):
    if not isinstance(self.age, int):
        raise TypeError("Age must be an integer.")
```

or use a runtime validation library.

# 13. Final cheat sheet

## `subprocess`

```
result = subprocess.run(
    ["command", "argument"],
    capture_output=True,
    text=True,
    check=True,
)
```

Use:

```
result.stdout
result.stderr
result.returncode
```

Avoid `shell=True` with untrusted input.

## JSON

```
json.dumps(data)       # Python → string
json.loads(text)       # string → Python
json.dump(data, file)  # Python → file
json.load(file)        # file → Python
```

Use JSON for APIs and configuration.

## Pickle

```
pickle.dump(obj, file)
pickle.load(file)
```

Use only with trusted data. Unpickling can execute arbitrary code.[[docs.python](https://docs.python.org/3/library/pickle.html)]

## Dataclass

```
@dataclass
class User:
    name: str
    age: int
```

Use:

```
user = User("Toussaint", 20)
```

For mutable defaults:

```
items: list[str] = field(
    default_factory=list
)
```

For JSON:

```
json.dumps(asdict(user))
```

The main design rule is:

```
subprocess → external processes
json       → portable structured data
pickle     → trusted Python-only serialization
dataclass  → clean structured Python objects
```

For your AI projects, a strong default is to use **dataclasses internally**, **JSON at application/API boundaries**, **subprocess for controlled external tools**, and **pickle only for trusted local artifacts where Python-specific object preservation is genuinely useful**.
